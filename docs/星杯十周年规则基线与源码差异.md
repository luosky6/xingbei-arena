# 星杯十周年规则基线与源码差异

> 状态：规范基线 v0.1，已逐页核对本地《星杯十周年说明书》印刷页 00-21，并解析其官方二维码资料入口。
>
> 目标：为竞技场建立“规范规则”和“程序实现”分离的可审计规则真源。本文不把现有源码自动视为官方规则，也不把单一说明书误当成所有扩展、卡面与 Q&A 的全集。

## 1. 结论

星杯规则需要分成两条并行事实链：

1. **规范事实**：桌游在某一版本下应该如何裁定。十周年说明书是核心规则的最高优先级来源；卡面、角色扩展卡、官方 Q&A、结算时间轴和勘误补足个别卡牌与角色技能。
2. **实现事实**：`noname_xingbei` 当前代码实际上如何执行。它是自动对局的运行时裁判，但不是规范规则的唯一来源。

当两者不一致时，竞技场必须记录差异，不能把程序结果静默回写成官方规则。训练数据同时保存 `normative_rule_version` 和 `engine_commit`，否则无法区分“AI 决策错误”和“引擎实现偏差”。

## 2. 来源等级与版本治理

| 等级 | 来源 | 用途 | 冲突处理 |
|---|---|---|---|
| S0 | 官方勘误、官方最新 Q&A、官方结算时间轴 | 修正规则书与卡面歧义 | 同版本内优先级最高 |
| S1 | 对应版本正式说明书 | 核心术语、流程、上限、一般规则 | 被同版本 S0 明确修正时让位 |
| S2 | 对应版本卡面、角色扩展卡、专属卡 | 个别牌与技能的条件和效果 | 特殊规则覆盖一般规则 |
| S3 | 官方技能表、版本改动表 | 建立角色/技能全集和版本差异 | 需绑定发布日期与适用包 |
| I0 | `noname_xingbei` 源码与动态回放 | 记录当前程序行为 | 不覆盖 S0-S3，只生成差异 |
| C0 | 百科、教学、赛事整理、社区裁定 | 解释、发现遗漏、交叉验证 | 不直接成为强制规范 |

本地 PDF 印刷页 20 的二维码指向官方“星杯传说 Q&A”资料库。当前检出的补充资料包括：

- 十周年二扩说明书终末 v25.10.13；
- 十周年二扩“无法行动”专项 v25.4.5；
- 十周年二扩结算时间轴；
- 十周年至补完包技能表；
- 历届改动表；
- 星杯宇宙与角色列表。

因此规则库必须支持版本线，而不是维护一个会被后续资料覆盖的扁平 `rules.md`。

## 3. 十周年核心规则

### 3.1 对局、阵营与胜利

- 基础说明书支持 4 人和 6 人团队对战，分别为 2v2、3v3；后续资料增加 8 人模式，属于版本扩展，不能反向写成基础说明书原文。
- 双方初始士气各 15；后续 8 人模式使用 18。
- 任一条件成立立即结束：对方士气降至 0 或以下；己方获得 5 个星杯。
- 每位玩家使用一个角色；同阵营共享士气、战绩区星石与星杯，但手牌、治疗、能量、角色状态和指示物属于个人。
- 初始手牌 4，基础手牌上限 6，治疗上限 2，能量上限 3，战绩区星石上限 5，普通攻击牌基础伤害 2。

### 3.2 回合与行动经济

标准回合语义为：

`回合开始前 -> 回合开始时 -> 行动阶段开始前 -> 行动阶段开始时/启动 -> 执行一个行动 -> 回合结束`

- 正常情况下，行动阶段必须且只能执行一个行动。
- 行动分为攻击行动、法术行动、特殊行动。
- 启动不消耗行动，但每回合最多启动一次；启动后本回合不能执行购买、合成、提炼，只能执行攻击或法术行动。
- 追加行动默认可以不执行；这与正常行动“必须执行”不同，动作模型必须显式区分。
- 中毒、虚弱在行动阶段开始前结算，早于启动。

### 3.3 攻击、应战与命中

- 攻击无距离限制，但只能选择对手。
- 被攻击者可选择：同系攻击牌应战；使用圣光或强制移除圣盾抵挡；不处理并承受攻击。
- 应战使原攻击未命中，并产生一次应战攻击；应战攻击不能以刚才攻击自己的角色为目标。
- 暗灭可以应战非暗系攻击；暗灭本身不能被应战，只能由圣光或圣盾抵挡。
- 主动攻击命中为己方战绩区增加 1 宝石；应战攻击命中增加 1 水晶。即使伤害最终被治疗完全抵御，只要攻击已经命中，仍然产生星石。
- 主动攻击消耗攻击行动，应战攻击不消耗当前玩家的攻击行动。攻击性质不能在结算中任意互换。

### 3.4 法术与五种基础法术牌

- 法术行动包括主动使用法术牌和发动标记为法术的角色技能；圣光不能作为主动法术打出。
- 中毒：放置到任意角色面前，在其行动阶段开始前造成 1 点法术伤害③并移除；允许多个中毒，按从当前玩家开始的座次顺序结算。
- 虚弱：每名角色面前最多一个；触发时选择跳过行动阶段，或强制摸 3 后继续行动，选择后移除。
- 圣盾：受到攻击或魔弹时必须移除并令其未命中，不能主动保留圣盾选择硬吃。
- 圣光：仅在受到攻击或魔弹等明确允许的响应窗口使用，使其未命中。
- 魔弹：初始目标为传递方向最近的对手，基础 2 点法术伤害；目标可以打出魔弹继续传递，每传一次伤害 +1，或以圣光/圣盾终止。一次传递过程中方向不改变，每名角色每轮参与一次；全员参与后可进入下一轮，伤害不清零。

### 3.5 三种特殊行动

- 购买：仅当摸 3 后不会爆牌时可执行；摸 3，并尝试增加 1 宝石与 1 水晶。战绩区已有 4 枚时选择其中一种，已满 5 枚时仍可购买但不增加星石。
- 合成：至少有 3 枚团队星石且摸 3 后不会爆牌；摸 3，将任选 3 枚星石换成 1 星杯，并使对方士气 -1。
- 提炼：战绩区至少有 1 枚星石且个人能量未满；将最多 2 枚团队星石转为个人能量。
- 能量一旦提炼不能替换，只能消耗。需要水晶的必杀可以用水晶或宝石支付；需要宝石的必杀只能用宝石支付。

### 3.6 伤害、摸牌、爆牌与士气

- 伤害分为攻击伤害与法术伤害。每承受 1 点伤害，从牌库摸 1 张牌；伤害来源是角色，不是卡牌。
- 购买、合成、虚弱等为非伤害摸牌，不能被治疗抵御。
- 任何原因导致手牌超过上限都立即爆牌；玩家暗置弃到上限，每弃 1 张使己方士气 -1。
- 治疗由受伤者自行决定是否使用以及使用多少，每 1 点抵御 1 点伤害；完全抵御伤害不倒推“攻击未命中”。
- 治疗只能抵御伤害摸牌，不能抵御非伤害摸牌。

### 3.7 伤害时间轴

规范时间轴共有六点：

1. ① 攻击/法术发动阶段；
2. ② 命中判定阶段；
3. ③ 造成伤害阶段，确定将造成的伤害量；
4. ④ 治疗响应阶段；
5. ⑤ 实际产生伤害阶段，确定治疗后的伤害量；
6. ⑥ 实际承受伤害阶段，执行伤害摸牌并检查爆牌、士气与后续响应。

`③-⑥` 是伤害结算段。角色技能不是简单按代码注册顺序执行，而必须按数字时点、文字先后、插入结算和座次规则共同排序。

### 3.8 通用技能语义

- 技能分普通、独有、专属、必杀；类别分被动、响应、启动、法术。
- 同一时点同名响应技能只能发动一次，禁止重复响应；不同技能同一时点如无特殊规定，由拥有者选择顺序。
- 发动条件与效果必须分离：条件不满足则不能发动；效果目标存在但部分无效，仍可视为部分/不完全发动。
- 所有效果需要合法目标；“丢失目标”与“效果没有实际收益”不是一回事。
- 溢出通常不阻止发动，超出上限部分被舍弃；只有文本明确“达到上限时不能……”才改变合法性。
- 中毒、虚弱、圣盾及部分独有牌属于基础效果。同一角色面前同名基础效果通常最多一个，中毒等明确例外可以共存；专属效果不能被“移除基础效果”移除。

## 4. “无法行动”不是一个简单按钮

通用流程是：当玩家除提炼外没有行动可能时，可展示手牌并宣言无法行动；经认可后弃置全部手牌、摸等量牌，继续本次行动且不能执行特殊行动。仍可提炼不妨碍宣言。

官方补充规则进一步建立了“行动可能性责任”体系：

- 玩家不能主动放弃已有行动，也不能主动抹杀自己或他人的行动可能。
- 摸牌通常视为增加行动可能；主观弃牌、部分启动与盖牌可能构成抹杀行动可能。
- 有能够增加行动可能的启动时，通常必须先启动；启动只会减少可能时，应在启动前宣言。
- 某些角色必须先发动指定技能，例如女武神的秩序之印、蝶舞者的舞动、魔法少女的魔爆冲击等。
- 某些情况下主动使用治疗把伤害降为 0 会被视为恶意制造无法行动；由队友的灵魂连接转移则可能合法。
- 被挑衅时，若本来会进入无法行动判定，规则可能改为直接跳过行动阶段。
- v25.4.5 专项表覆盖了数十名角色与大量边界场景，不能仅靠“当前是否存在一张可用牌”判断。

这意味着合法动作生成器需要一个独立的 `action_possibility` 证明系统，输出：现有可能、强制启动、禁止主动消除的资源、宣言时点、宣言后限制和判罚原因。

## 5. 官方资料规模对 AI 的含义

官方“十周年至补完包技能表”当前可识别：

- 437 条角色技能记录；
- 72 个角色/变体名称；
- 基础、一扩、二扩、特典、补完五类来源；
- 38 个启动、115 个法术、100 个被动、184 个响应条目。

竞技场源码扫描（引擎指纹 `sha256:87969d...`，154 个文件）另外发现 119 个角色对象、640 个技能对象，其中 632 条成功解析；两组数字不能直接相加：官方表按卡表/版本记录，源码按运行时对象（含变体、备份技和重复实现）统计。当前有 147 条技能缺少可抽取中文说明、424 条缺少 AI 元数据，均保持待审队列，不自动当成“无效果”。

因此 AI 不能只建立“角色强度分”。最小知识单元应是：

`版本 + 角色形态 + 技能 + 时机 + 条件 + 成本 + 目标 + 直接效果 + 延迟效果 + 资源变化 + 行动可能变化 + 座次依赖 + 组合标签`

同一角色还需要按座次、队友、对手、BP 顺位和团队角色重新估值。尤其是响应技数量最多，若事件桥只截获主动出牌，训练环境会遗漏最重要的一类决策。

## 7. 规则数据模型

每条规则至少保存：

```yaml
rule_id: damage.timeline.04.heal
title: 治疗响应阶段
scope:
  edition: xingbei_10th
  expansions: [base]
  modes: [2v2, 3v3]
normative:
  statement: 受伤者在④决定是否以治疗抵御部分或全部伤害
  sources:
    - type: rulebook_pdf
      print_page: 18
      authority: S1
implementation:
  engine_commit: <git-sha>
  source_refs: []
  observed_behavior: null
difference:
  status: unverified
  severity: unknown
adjudication:
  status: accepted_normative
  tests: []
```

角色技能条目另加 `timing_points`、`once_scope`、`mandatory`、`condition_ast`、`effect_ast`、`action_possibility_delta`、`seat_relation` 和 `synergy_tags`。

## 8. 收敛测试

1. 为核心规则建立最小场景：攻击/应战/暗灭、治疗完全抵御、爆牌、购买满战绩区、合成、提炼、虚弱、中毒、圣盾、魔弹多轮。
2. 为①-⑥每一时点建立可插入一个角色响应的夹具，验证事件顺序与父子事件。
3. 将“无法行动”专项表转换为参数化测试；每个角色至少包含一个可宣言和一个不可宣言场景。
4. 将官方技能表全部映射到源码角色/技能 id；未映射、重复映射、版本冲突都令覆盖门禁失败。
5. 对转换 FAQ 建立矩阵测试，分别验证系别、命格、卡种、应战、封印和增伤视图。
6. 对同一 seed 同一动作序列同时记录规范期望和引擎实际；差异进入 `rules-diff`，未经裁定不得进入金标训练集。

完成标准不是“文档写完”，而是：S0-S3 中所有可机器化规则都有 id、版本、来源和测试；全部可用角色与技能均有映射；所有未裁定差异被训练管线隔离。
