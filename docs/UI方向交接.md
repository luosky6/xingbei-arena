# 无名星杯 UI 方向交接说明

> 状态：已从当前 AI/规则工作流中拆出，后续由独立 agent 接手。本文是 UI 方向的边界、现状和验收入口；不会把 UI 计划项误报为已完成。

## 1. 交接范围

UI agent 只负责 `noname_xingbei` 的界面层，以及 `xingbei-arena/ui-overlay/` 中不改变规则语义的视觉覆盖层，目标包括：

- 现代主题、设计 token、响应式布局和可访问性；
- 对局 HUD、卡牌详情、选择反馈、首页/模式选择、BP/CM、观战和结算页；
- Playwright 截图基线、视觉回归和 UI 交互行为回归；
- 将引擎已有状态转换为稳定的视图模型，但不重新裁定规则。

以下内容不属于 UI agent：规则真源、角色/技能语义裁定、决策策略、合法动作判定、自对弈、训练、评测和晋级。

## 2. 当前快照

- 已存在可逆现代主题：`ui-overlay/install.js`，通过 `XB_MODERN_UI=1` 启用；默认仍是 legacy，便于对照。
- 已有截图产物：`runtime/ui-screenshots/legacy.{png,json}` 与 `runtime/ui-screenshots/modern.{png,json}`。
- 现代主题目前只覆盖运行时主题和基础面板，选角/BP/观战专属组件仍未完成。
- 引擎 `noname_xingbei` 当前未被竞技场改写；UI agent 如需修改引擎，应保持规则事件和公开状态字段兼容。
- 竞技场测试中已有 UI overlay 幂等性与现代主题基础检查，但尚未形成完整页面视觉矩阵。

## 3. 建议接手顺序

1. A0：固定 1366×768、1920×1080、平板横屏、手机横屏视口；录制首页、模式、选角/BP、初始对局、选牌、选目标、资源变化、结算页基线。
2. A1：先完成 CSS tokens、字号、颜色、动效降级、高对比度、色弱辅助和旧主题回退。
3. A2：把士气/星石/星杯/战绩区改成稳定 DOM 节点的增量 HUD，禁止每次更新整块 `innerHTML`。
4. A3：统一卡牌、合法选项、禁用原因、按钮层级、动效消费和键盘/触控操作。
5. A4：完成首页、模式配置、BP/CM、观战和结算信息架构。
6. A5：做响应式、性能、无障碍和视觉回归；行为摘要必须与改造前一致。

## 4. 与 AI/规则方向的接口约束

- UI 只消费公开视角状态；不得展示对手隐藏手牌、暗置牌或未经授权的候选动作。
- `match_id`、`seed`、`policy_id`、`rules_profile` 等调试字段可以在观战/调试模式显示，但不能参与规则判定。
- 选择控件应保留竞技场生成的稳定 `option_id`，不要用显示文本或 DOM 顺序替换它。
- UI 动画必须在引擎事件完成后消费，不能通过动画回调推进事件。
- 任何引擎层修改都必须先运行规则事件摘要回归；UI 改动不能改变伤害、资源、胜负、座次或技能事件语义。
- UI agent 的结果应附带截图、视口、行为摘要和性能数据；不要用单张截图宣称完成。

## 5. 接手验收条件

- 核心页面在四类视口无 P0/P1 遮挡，键鼠与触控热区可用。
- 新主题和 legacy 可切换，切换不改变同一种子下的规则事件摘要。
- 资源 HUD 增量更新无明显闪烁，长局 DOM 节点数量和内存不持续增长。
- 隐藏信息按视角隔离；观战布局不泄露玩家私有信息。
- Playwright 行为回归和按页面配置的视觉差异阈值均通过。

## 6. 运行入口

在 `xingbei-arena` 目录：

```text
npm test
npm run ui:screenshot
XB_MODERN_UI=1 npm run selfplay
```

Windows PowerShell 可将 `XB_MODERN_UI=1` 改为 `$env:XB_MODERN_UI='1'` 后再运行命令。UI 交接完成后，将截图/回归报告和本文件一起交回项目维护者即可。
